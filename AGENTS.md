# Instructions for AI agents

* Be consistent with the goals of the project (to aid human exploration of
  streams of performance-related events, with a focus on
  microarchitecture-related functionality)
* Be cohesive with the overall design of the existing tool and take into
  account user-interface patterns and not significantly disrupt existing users
  or their configurations/workflows without good reason.

## Testing

    hatch test

## Formatting & Linting

To check:

    hatch fmt --check

To fix all auto-fixable issues:

    hatch fmt

## Code Requirements

Most of these are enforced by CI in the PR, but specifically:

* All tests must pass
* Code must meet style/formatting guidelines

## Labeling

Any code modifications made by AI agents should be labeled as such, ideally in
a git commit message *and* in the code. Labeling via git messages is
*absolutely* required.

For git messages, use the following commit template:

    <SUMMARY OF CHANGE, max of 50 characters>
    <DETAILS OF CHANGE, wrap at 72 characters>

    Assisted-by: <AGENT NAME>:<MODEL VERSION>

For source comments (code-only), if a file/class is added with AI, there should
be a comment indicating so, in the following format:

    Assisted and/or generated by <AGENT NAME>:<MODEL VERSION>

Comments can be grouped semantically by block/function/class/file, etc.
Per-line labeling is *not* required. Only add a comment if a large amount of
code is generated from scratch.
